## Steps (in order)
1. 👤 Decide repository visibility (free GitHub Pages needs a *public* repo; Pages stays disabled for now).
2. 👤 Create an empty GitHub repository `qr-pocket` (no README/licence/.gitignore).
3. 👤 Settings → Actions → General: Actions allowed; **Workflow permissions: Read repository contents**. Leave Pages = None.
4. 👤 **Before pushing**, tell me and I will re-verify the pinned action SHAs in both workflow files (they were read from the GitHub API on 2026-10-21).
5. 👤 In the project folder (in Claude Code type `! <command>`; git only — no npm):
   ```
   git init -b main
   git add -A
   git commit -m "Phase 0-2: specs, designs, SPEC-001 source and CI config"
   git remote add origin https://github.com/<user-or-org>/qr-pocket.git
   git push -u origin main
   ```
6. 👤 GitHub → Actions → **Generate lockfile (manual)** → Run workflow (branch `main`). Download the `package-lock` artifact (or `gh run download <id> -n package-lock`) and save `package-lock.json` into the project root. (CI on `main` will fail at `npm ci` until the lockfile exists — expected.)
7. 👤 Commit the lockfile on a branch, push it and open a pull request into `main` (CI runs on pull requests and on pushes to `main`):
   ```
   git switch -c phase-2-core
   git add package-lock.json
   git commit -m "Add package-lock.json generated by CI"
   git push -u origin phase-2-core
   ```
   then open the PR on GitHub (or `gh pr create --fill`). That PR run is the first real CI run.
8. Read the run: GitHub → Actions → CI → latest run (all steps run even when one fails, so one run shows every problem). Share the run URL with me, or run `gh auth login` once so I can read logs with `gh run view --log-failed`. Download the `reports-<sha>` artifact for the Playwright report and `size-report.txt`.
9. I classify failures (test defect / product defect / environment), fix the root cause, and you push the fix. Repeat until green; I record the evidence (run URL, SHA, counts) in `docs/PROGRESS.md` and `docs/TRACEABILITY.md`.

## What the first run is expected to tell us (honest expectations)
This is the first execution of everything. Expect some failures: type or lint issues, selector or timing problems in browser tests, an axe finding, a bundle-size number, and — the one that matters for the product — whether the **ZXing** decoder reads UTF-8/Arabic payloads that have no ECI marker (T-001-2b). Any ZXing mismatch is a real interoperability finding to decide on (ADR-014), not just a test to silence.

## What CI runs (`.github/workflows/ci.yml`)
Node 22 → `npm ci` → typecheck → lint → Vitest → `vite build` → size gate (150 KB gzip target, measured) → `npm audit --omit=dev` → licence check → Playwright (Chromium, axe, 320–430 px, text scaling, CSP/privacy) → artifacts. No deploy. Pages deployment (`deploy.yml`, manual) is Phase 5 and needs G3.
