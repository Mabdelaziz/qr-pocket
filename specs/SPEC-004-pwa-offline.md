# SPEC-004 — PWA install and offline

Status: IN PROGRESS (Phase 4, branch `phase-4-pwa`) — refined 2026-10-21 per owner Phase 4 authorisation.

## Goal
An installable app that works offline after its first load, with user-controlled updates, a respectful install prompt, and a documented way to recover from a bad service worker — all under `/qr-pocket/` and without caching any user data.

## User story
US-09, US-10.

## In / out of scope
In: web manifest and generated icons, service worker (precache of build output only), prompt-based updates, offline/update/ready notices, custom install prompt with dismissal policy, recovery procedure, cross-browser smoke. Out: push notifications, background sync, share target, shortcuts, runtime caching of anything, iOS-specific install guidance, deployment (Pages stays disabled).

## Dependencies
SPEC-001–003 (the app), ADR-005, ADR-009, ADR-017 (this phase). `vite-plugin-pwa` 2.0.0 with `workbox-build` / `workbox-window` 7.4.1 (dev-only; the plugin's client helper is NOT used, so no extra runtime code ships).

## UI impact
Header offline chip; inline notice bars under the header (offline, update available, ready to work offline, install); screen mocks N1–N5 in `docs/design/mockups/`.

## Interface / data contracts
**Manifest** (`/qr-pocket/manifest.webmanifest`): `name` and `short_name` "QR Pocket"; `id`, `start_url`, `scope` = `/qr-pocket/`; `display: standalone`; `theme_color #FFFFFF`; `background_color #F5F7FB`; `lang en`; icons: `icons/icon-192.png` (192, any), `icons/icon-512.png` (512, any), `icons/icon-maskable-512.png` (512, maskable), `icons/icon.svg` (any).
**Icons** generated at build time by `scripts/generate-icons.mjs` (no image library, no local tools): master SVG, 192 and 512 PNG, 512 maskable PNG. Blue `#155EEF`, white QR-inspired mark, rounded square; maskable = full-bleed blue with the artwork inside the central circle of radius 40% of the icon (safe zone).
**Service worker** (`/qr-pocket/sw.js`, scope `/qr-pocket/`): generated by Workbox; precaches the hashed build assets, `index.html`, manifest and icons **only**; no runtime caching routes; cache id prefix `qr-pocket`; `cleanupOutdatedCaches`; `clientsClaim`; `skipWaiting` only on a `SKIP_WAITING` message from the page.
**Registration** (`src/pwa/register.ts`): production builds only; update found while a controller exists → update bar; first install (no controller) → one-time "Ready to work offline"; the page never reloads unless the user presses **Reload**.
**Install prompt** (`src/pwa/install.ts`): shown only if the browser fired `beforeinstallprompt`, at least one QR has been shown (engagement), not in standalone mode, not after `appinstalled`, not within 30 days of "Not now" / a dismissed native prompt, and not more than once per 7 days when ignored; at most once per page session. State in `localStorage` key `qr-pocket.install` (try/catch; absence of storage = never persists). Wording: title "Keep QR Pocket on your phone"; text "Install QR Pocket for quick access and offline QR creation. No account needed."; buttons "Install app" and "Not now". Without the event nothing is shown or promised (browser menus still offer installation).
**CSP**: adds only `worker-src 'self'; manifest-src 'self'` to the existing policy.
**Build id**: `__BUILD_ID__` (default `v1`; `QR_POCKET_BUILD_ID` overrides) is exposed as `<html data-build>` and changes the hashed bundle, which lets tests simulate two deployments (`npm run build:v2` → `dist-v2`).

## Behaviour
- Offline: chip "Offline" in the header and a bar "You're offline. Creating, saving and exporting still work." while `navigator.onLine` is false; "Back online." announced politely. Nothing is blocked.
- Update: bar "A new version is ready." with **Reload** and **Later**; if the text field contains unsaved text the bar also says that reloading clears it. **Later** hides the bar for this page session. The page continues untouched (typing, dialogs, Saved list) until Reload; Reload activates the waiting worker and reloads once.
- IndexedDB is never touched by the service worker, a service-worker update, or the recovery procedure; records persist across reloads, offline use and updates.
- Recovery: `docs/SW_RECOVERY.md` (kill-switch worker that deletes `qr-pocket*` caches and unregisters, rollback by redeploying a previous build, user-level steps). Verified in tests.
- Failure: if registration fails or service workers are unsupported the app works online, silently.
- Edge: opening `/qr-pocket` without the slash is redirected by the host (not available offline); new tabs offline; install prompt event arriving before the app finished loading.

## Security / privacy / accessibility
Only static build output is cached; no payload, title or IndexedDB record ever enters Cache Storage (tested by URL and body). No third-party scripts, fonts or CDNs. Notices: one announcement channel per event (polite status region; none duplicated by an alert). Bars never cover navigation or primary actions; targets ≥ 48px; rem-based text (150%/200%); no horizontal overflow at 320px.

## Acceptance criteria
- AC1 Given the production build, then the manifest has the fields above, every listed icon exists with the exact size, the maskable icon keeps all white artwork inside the safe circle, and the "any" icon has transparent rounded corners.
- AC2 Given a first online load, then exactly one service worker is registered at `/qr-pocket/sw.js` with scope `/qr-pocket/`, and all cache names start with `qr-pocket`.
- AC3 Given the app loaded once and the service worker active, when the browser goes offline and the page is reloaded (also in a new tab), then the app loads.
- AC4 Given offline, then Generate, Save, Saved list, Open and PNG Download work, saved records survive reloads, and going back online hides the offline notices.
- AC5 Given a newer deployment, when the browser checks for updates, then an update bar appears; until Reload is pressed the page does not reload, typed text and dialogs are untouched, and the running build id is unchanged.
- AC6 Given Reload is pressed, then the page reloads once into the new build, saved records are intact, and only the new build's precache remains.
- AC7 Given **Later** is pressed, then the bar disappears, nothing reloads, and the current build keeps running.
- AC8 Given any use (typing, saving, exporting) online or offline, then no Cache Storage entry URL or body contains the payload or title, and the caches contain only build assets.
- AC9 Given offline/online transitions and first install, then the chip/bars appear and disappear correctly and polite announcements are made once ("Ready to work offline." only once per browser profile).
- AC10 Given the install-prompt policy, then it is not shown on load, appears only after a QR has been shown, respects "Not now" for 30 days and ignored prompts for 7 days, is hidden after installation and in standalone mode, calls the browser's native prompt on "Install app", and never appears when the browser fires no event.
- AC11 Given the notices and prompt, then axe finds no WCAG 2.x A/AA violations, there is no horizontal overflow at 320px and at 150%/200% text, and targets are ≥ 48px.
- AC12 Given the kill-switch worker is deployed over a working one, then after an update check the caches named `qr-pocket*` are deleted, the worker unregisters, IndexedDB records are untouched, and the app still loads from the network.
- AC13 Given Firefox and WebKit, then the core flows (generate, save, reload persistence, Saved list, rename/delete dialogs, PNG download) and the manifest/icon files work.
- AC14 Given the CSP, then only `worker-src 'self'` and `manifest-src 'self'` were added; no inline script/style; no console errors; no cross-origin requests.
- AC15 Given the production build, then the initial load (HTML + JS + CSS, gzip) stays ≤ 150 KB; the service worker and Workbox runtime are reported separately.
